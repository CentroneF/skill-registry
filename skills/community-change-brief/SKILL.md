# Community change brief

Read the current repository's request, README, applicable project guidance and relevant source files. Prepare a short brief in `docs/change-brief.md` unless the user specifies another location.

Include:

- Intent: the requested outcome and acceptance criteria.
- Repository context: the project role and relevant file paths.
- Proposed change: the approach and unresolved questions.
- Verification: concrete checks, distinguishing proposed checks from checks actually run.

Keep the brief specific to the current repository. Prepare the brief without implementing the feature unless the user explicitly expands the scope.
